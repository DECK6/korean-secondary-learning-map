# v0.6.0-candidate 릴리스 보고서

릴리스 기준일: 2026-09-06

## 변경 목적

v0.5는 "공식 문서가 직접 뒷받침하는 관계만 남긴다"는 결정을 관계 데이터에 적용했다. 그 결과 official 층은 근거가 단단해졌지만 밀도가 낮아졌고(중학교 24과목 중 15과목, 고등학교 759과목 중 148과목), 튜터 에이전트가 쓸 학습 순서 정보가 부족해졌다. v0.6은 그 공백을 **근거의 등급을 낮추는 방식이 아니라 층을 나누는 방식**으로 메운다. 동시에 초등 저장소와 공유하는 K-12 코어 어휘를 온톨로지로 승격해 두 저장소가 같은 질의로 읽히게 만들고, PDF 추출 텍스트의 공백 결함과 쪽번호 인용 오류처럼 v0.5까지 남아 있던 정합 문제를 정리한다.

작업은 R1~R5 다섯 라운드로 진행했고 실행 원장은 `docs/plans/PROGRESS.md`, 계약은 `docs/plans/2026-09-05-k12-relation-vocabulary-spec.md`다.

## 1. PDF 텍스트 공백 위생 (T3)

`pdftotext -layout`은 한국어 줄바꿈을 단어 중간에서 끊기 때문에 추출 텍스트에 `추 론하기`·`밤 하늘`·`유 용성` 같은 어절 내부 공백이 남았다. pdftotext 옵션으로는 해결되지 않아 `scripts/lib/text-normalize.mjs`에서 **코퍼스 증거 결합** 방식으로 처리한다.

- 병합 판정은 과목별 하드코딩이 아니라 공식 텍스트 코퍼스 자체가 결정한다. 어떤 토큰 쌍은 (a) 결합형이 코퍼스에서 단어 시작으로 관측되고 (b) 띄어 쓴 형태가 **같은 줄 안에서** 관측되지 않을 때만 병합한다. 같은 줄 조건이 핵심이다 — 줄바꿈 결함이 자기 자신의 띄어쓰기를 정당화하지 못하게 막는다.
- 임계값은 접두 2~12음절, 결합 증거 3회 이상(1음절+1음절 쌍은 20회 이상), 결합형이 띄어쓴 형태보다 4배 이상 우세. `할 수 있다`·`및`·`등`·`각`처럼 정상적으로 홀로 서는 1음절 토큰은 allowlist와 `NEVER_JOIN_SINGLE_TOKENS`로 보호한다.

결과(현재 데이터 기준):

| 대상 | 어절 내부 공백 의심 | 총계 |
| --- | ---: | ---: |
| 중학교 성취기준 요약 | **0** | 714 |
| 중학교 주제 라벨·증거 | 6 | 2,160 |
| 중학교 영역명 | 3 | 149 |
| 고등학교 성취기준 요약 | 1,137 | 50,749 |

고등학교 잔량은 결함이 아니라 **직업계 전문교과의 실제 1음절 어휘**다(`빅`·`맵`·`카`·`측`·`광` 등 조사·약어·외래어 음절이 다수). 이들은 코퍼스 증거상 결합형이 우세하지 않아 병합 대상이 아니며, 게이트도 상한(1,800)으로만 관리한다.

**ID 불변**: 위생 처리는 표시 문자열만 바꾼다. 중학교 성취기준 714·주제 2,160, 고등학교 성취기준 50,749·주제 50,749의 ID 집합이 처리 전후로 동일함을 게이트가 사전 스냅숏과 대조해 확인한다.

**부수 정정**: `ontology/shapes.ttl`의 `slm:CoverageGapShape`가 status enum을 `("open" "in-progress" "closed" "accepted")`로 두어 `schema/core.schema.json`의 `("open" "in-review" "resolved" "accepted")`와 어긋나 있었다. SHACL 쪽을 JSON 스키마에 맞춰 고쳐 v0.5 이전부터 있던 불일치를 없앴다.

## 2. 관계 2층 분리와 후보 층 (R2-E)

K-12 공통 계약 v1에 따라 학습 관계를 두 층으로 나눈다.

- **official**: 공식 문서가 선수 관계를 직접 말한 것만. `layer: official`, `relationKind: required-prerequisite`, `basisKind: official-source`, `reviewStatus: internal-reviewed`.
- **pedagogical-candidate**: 저장소가 규칙으로 만든 권장 순서. `layer: pedagogical-candidate`, `relationKind: recommended-before`, `reviewStatus: candidate`.

모든 관계 레코드는 한정자 5종(`layer`·`relationKind`·`basisKind`·`scope`·`reviewStatus`)을 갖는다. 현재 값 분포는 아래와 같다.

| 파일 | 건수 | layer | basisKind | scope |
| --- | ---: | --- | --- | --- |
| `middle/learning-relations.json` | 56 | official | official-source 56 | same-course 56 |
| `middle/learning-relations.candidate.json` | 1,988 | pedagogical-candidate | decomposition-order 1,446 / official-code-order 542 | same-standard 1,446 / same-domain 542 |
| `high/learning-relations.json` | 171 | official | official-source 171 | same-course 160 / cross-course 11 |
| `high-vocational/learning-relations.json` | 298 | official | official-source 298 | cross-course 207 / same-course 91 |
| `high/learning-relations.candidate.json` | 2,353 | pedagogical-candidate | official-code-order 2,353 | same-domain 2,353 |
| `bridges/elementary-transitions.json` | 290 | official | official-source 290 | cross-school-level 290 |
| `bridges/elementary-transitions.candidate.json` | 3,180 | pedagogical-candidate | repository-authored 3,180 | cross-school-level 3,180 |

**official에서 뺀 39건**: 고등학교 과목 설계 연계 문장을 "과목 A의 마지막 성취기준 → 과목 B의 첫 성취기준"으로 투영한 `recommended-before` 학습 관계 39건을 official 학습 관계에서 제거했다(508 → 469). 계약이 official 층을 전건 `required-prerequisite`로 정의했기 때문이다. 같은 근거의 **과목 수준** 관계 39건은 `high/course-relations.json`에 `relationKind: recommended-before` / `basisKind: official-source`로 그대로 남아 있어 근거 손실은 없다.

**후보 층 생성 규칙** (`scripts/build-candidate-relations.mjs`, `bun run build:candidates`):

- `R-CODE` — 같은 과목·같은 영역에서 성취기준 **코드 순서**가 인접한 쌍. `basisKind: official-code-order`. 코드 번호는 고시가 부여했지만 고시가 이를 선후로 주장한 적은 없으므로 official이 아니다.
- `R-FACET` — 한 성취기준의 핵심(core) 주제 → 같은 성취기준의 facet 주제. `basisKind: decomposition-order`. **분해 순서가 저장소 산물**임을 basis 문장에 명시한다.

고등학교 후보는 `programScopes`에 `all-high-schools`가 있는 231과목만 대상이며 직업계 전문교과 528과목은 0건이다(R-FACET도 고등학교는 0건 — 고등학교 주제는 전건 `facetKey: core`다). 8절의 릴리스 분리 이후 직업계 릴리스에는 후보 관계 파일 자체가 없고, 스키마가 그 컬렉션을 허용하지 않는다. 합집합 DAG를 지키기 위해 순환을 만드는 고등학교 후보 간선 3건은 결정적으로 제외했다.

**과목 커버리지**

| 학교급 | official | 후보 | 두 층 합집합 |
| --- | --- | --- | --- |
| 중학교 (24과목) | 15 | 24 | **24 / 24** |
| 고등학교 (759과목) | 148 (주제 수준: 일반 87 + 직업계 61) / 179 (과목 관계 포함) | 231 | **292 / 759** |

**facet 공통 어휘 8종**: 중학교 주제의 과목별 24종 키는 `facetKeyDetail`로 옮기고, `facetKey`에는 공통 8종을 담는다. 현재 분포는 `core` 714 / `application` 332 / `procedure` 296 / `inquiry` 274 / `communication` 228 / `reflection` 221 / `representation` 73 / `concept` 22이며 고등학교 50,749개 주제는 전건 `core`다. 주제 ID 해시 입력은 `facetKeyDetail`이라 ID는 전건 불변이다. 사상 근거는 `docs/decisions/2026-09-05-facet-mapping.md`.

**쪽수 정정 (−6)**: `scripts/lib/official-relation-specs/math.mjs`가 인용한 쪽번호는 별책8의 **PDF 페이지**였다. 별책8은 표지·차례가 번호 없이 6쪽을 차지하므로 **인쇄 쪽번호 = PDF 페이지 − 6**이다. 이 오프셋은 초등 저장소의 같은 별책 채굴에서 먼저 드러났고 본 저장소의 추출 텍스트 쪽 바닥글로 재확인했다. `math.mjs`의 62개 튜플 전부를 인쇄 쪽번호로 고쳤다. 나머지 45개 사양 모듈은 원문 대조 결과 이미 인쇄 쪽번호를 쓰고 있었다(별책별 오프셋은 −4·−6·−8·−10로 문서 안에서 일정).

관계 ID는 `sha256(선수 주제 | 후속 주제 | relationKind | basis)`이고 `basis`에 쪽번호가 들어간다. 쪽번호만 고치면 ID가 전부 바뀌어 "기존 IRI 비재발급" 원칙을 어기므로, `math.mjs`에 `idPageOffset: -6`을 두고 빌더가 **표시용 basis에는 인쇄 쪽번호를, ID 해시 입력에는 정정 전 PDF 페이지를** 쓴다. 정정 전후로 중학교 56·고등학교 469·bridge 290·전이 175의 ID 집합이 모두 같음을 확인했다.

## 3. STAS 근거원 조사와 판정 (T6)

한국교육과정평가원 학생평가지원포털(STAS)이 중학교 선수 관계의 근거원이 될 수 있는지 조사했다. 전문은 `docs/decisions/2026-09-05-stas-source-assessment.md`.

**수집 규모** — 2022 개정 전량, 무인증 GET만, 요청 간격 0.52초, 로그인·권한 우회 없음. 영수증은 `sources/stas/receipt.json`, 원본은 `.gitignore` 처리한 로컬 캐시다.

| 학교급 | 목록·상세 | 해설 보유 | 관련 성취기준 보유 | 평가준거·성취수준 보유 |
| --- | ---: | ---: | ---: | ---: |
| 초등학교 | 611 | 350 (57.3%) | 611 (100%) | 611 (100%) |
| 중학교 | 714 | 440 (61.6%) | 714 (100%) | 713 (99.9%) |
| 고등학교 | 3,261 | 1,683 (51.6%) | 1 (0.03%) | 3,256 (99.8%) |
| **합계** | **4,586** | 2,473 | 1,326 | 4,580 |

**코드 일치율** — 중학교 714/714 = **100%**. 초등 620 기준 98.55%(부족한 9건은 2024-3 고시 신설 「건강한 생활」로 STAS 미탑재), 고등학교 일반계 3,113 코드는 전건 일치.

**판정: 선수 관계 근거로 쓸 수 없다.** 선후를 말하는 필드가 STAS에 없다. 후보였던 `rltnAcvmtStdDtl`(관련 성취기준)을 전수 검증한 결과 이 필드는 **같은 영역의 형제 성취기준 전체에서 자기만 뺀 집합**이었다. 중학교 714건 전건이 예외 없이 그 정의와 일치했고, 같은 과목·영역 밖 참조는 초·중 통틀어 0건(0.00%)이다. 방향성도 없다 — 영역의 첫 코드는 나머지 전부를, 마지막 코드도 나머지 전부를 가리킨다. 학년 배정 필드도 `grdGrpNm` 학년군뿐이고 중학교는 전건 단일값이라 학년 진행(C계층) 채굴에도 쓸 수 없다.

이 판정에 따라 **중학교 official은 56건을 유지하고**, 부족분은 내용 체계표 코드 순서·분해 순서를 근거로 하는 후보 층(R-CODE 542 + R-FACET 1,446 = 1,988건)으로 돌렸다. `rltnAcvmtStdDtl`은 official 층은 물론 후보 층에도 **관계로는 넣지 않는다**(영역 소속 정보는 이미 `domainId`가 갖고 있다).

**재사용 조건**: STAS에는 공공누리 표시가 없고, 이용약관이 정보의 본래 목적 외 복제(제10조①2)·상업적 이용(제13조②7)·가공 판매(제16조②)를 제한한다. 따라서 평가 성취수준(A~E)·평가준거 문장은 **참고·교차검증 입력으로만** 쓰고 문장을 저장소 데이터나 배포물에 재수록하지 않는다. 산출물에는 코드·구조·기계적 파생만 넣고, 1차 근거는 NCIC 고시 별책(권리 상태 `cleared`)으로 유지하며 STAS는 `sourceRefs` **보조 출처**로만 기록한다.

STAS 레코드는 쪽수가 없으므로, 인용하려면 `printedPage` 대신 `{endpoint, acvmtStdSeq, collectedAt, sha256}` 형태의 **새 locator 종류**가 필요하다. 이번 릴리스는 그 어휘를 TBox·SHACL에 예약만 하고 데이터 배출은 하지 않는다(7절 참조).

부수 성과로 저장소의 **로마숫자 표기 불일치 76건**이 드러났다. STAS·고시 원문은 전각 `Ⅰ`(U+2160), 저장소는 라틴 `I`를 쓴다. 정규화하면 전부 붙는다 — 어느 쪽으로 통일할지는 후속 결정 사항이다.

## 4. 콘텐츠 오버레이 인프라 (R3-B0)

기계적으로 파생한 주제 콘텐츠와 사람이 근거를 읽고 쓴 초안을 **파일 수준에서 분리**한다.

- 위치·형식: `data/kr/<level>/content/<slug>.json`. 슬러그는 과목 라벨의 결정적 변환이며(`scripts/lib/content-overlay.mjs`의 표에 없는 라벨은 `course-<sha256 앞 12자리>`), 파일 헤더에 `contentKind`·`subjectKorean`·`authoredAt`·`sourceRefs`·`note`를 두고 `entries`에 주제 ID를 키로 항목을 담는다. 항목 필드는 `evidence`·`assessmentPrompts`·`misconceptions`·`sourceLocator`(`sourceId`·`printedPage`·`section`·`code`)·`note`이고, 최소 길이 계약은 증거 25자·평가 과제 40자·오개념 15자다.
- `contentKind`는 두 값만 허용한다. `mechanical-derivative`(성취기준 요약을 치환한 템플릿)와 `source-grounded-draft`(공식 해설 등을 읽고 새로 쓴 초안). 빌더가 오버레이를 주제에 병합하면서 이 값을 주제 레코드에 새긴다.
- UI는 `source-grounded-draft` 주제에 **'검토 초안' 배지**를 붙이고 배지가 없는 주제는 기계 템플릿임을 안내한다(`scripts/check-ui-artifacts.mjs`가 배지 문구를 검사). `bun run validate`가 오버레이의 빌드 반영 여부까지 확인하고, `dist/<level>/manifest.json`이 오버레이 파일과 스키마의 해시를 핀한다.

원칙은 분리다. **기계 파생은 근거 없이 대량으로 만들 수 있고, 집필 초안은 근거 문단을 지목해야 한다.** 두 종류를 같은 필드에 섞지 않고 `contentKind`로 갈라 두면 검토·승격·철회를 층 단위로 할 수 있다.

## 7. K-12 코어 TBox 통합 (R4)

초등·중등 두 저장소가 클래스와 속성을 각자 정의하고 있어 같은 개념이 두 이름으로 존재했다. v0.6은 공통 어휘를 `ontology/k12-core.ttl`로 뽑아낸다.

- **IRI** `https://dexa.art/learnmap/ontology/k12-core`, **versionIRI** `https://dexa.art/learnmap/ontology/k12-core/1.0.0`. 내용은 클래스 11개, 추상 관계 한정자 5개(`rdf:Property`)와 그 개념형·토큰형 하위 속성을 포함해 객체 속성 9개·데이터 속성 15개, SKOS 개념 체계 8개(facet·relation layer·relation kind·basis kind·relation scope·review status·content kind·locator kind)와 개념 38개다.
- **바이트 동일 사본**: 같은 파일을 초등·중등 두 저장소에 둔다. 현재 두 사본의 sha256은 `f015b4b8209669ed040a519c36da260d27eb3d641997e592b007a6a582cf0a97`로 동일하다. 파일 헤더에 `# k12-core-sync-sha256:` 기준 해시(그 한 줄을 제거한 나머지의 sha256)를 적어 두고, 각 저장소의 `tests/k12-core-sync.test.mjs`가 이 값을 재계산해 동기화를 검사한다. 두 저장소가 서로를 참조하지 않고 **각자 오프라인으로** 확인할 수 있다.
- **import는 선언하되 네트워크는 쓰지 않는다**: 두 TBox 모두 `owl:imports <https://dexa.art/learnmap/ontology/k12-core>`를 선언하고, 실제 로딩은 로컬 `ontology/k12-core.ttl`에서 한다. IRI가 아직 호스팅되지 않아도 빌드·검증이 돌아간다.
- **IRI 재발급 없음**: 기존 `slm:`(중등)·`lm:`(초등) IRI는 그대로 두고 `owl:equivalentClass` / `owl:equivalentProperty` / `skos:exactMatch`로 코어에 연결한다. 중등 `learning-map.ttl`에 정렬 공리 28개가 있다(클래스 6, `rdfs:subClassOf` 2, 속성 10 + `rdfs:subPropertyOf` 1, facet SKOS 매치 9).

**ABox 배출** — 빌더가 코어 어휘를 실제 그래프에 낸다.

| 코어 속성 | 배출 대상 | 값 |
| --- | --- | --- |
| `core:facetKey` | 학습 주제 | `core:facet-*` 8개 개념 IRI |
| `core:contentKind` | 학습 주제 전건 | `core:content-mechanical-derivative` / `core:content-source-grounded-draft` |
| `core:misconception` | 집필 초안 주제 | 한국어 리터럴 다중 |
| `core:contentSourceLocator` | 집필 초안 주제 | `core:SourceLocator` 노드 |
| `core:layerConcept` | 학습 관계·전이 전건 | `core:layer-official` / `core:layer-pedagogical-candidate` |

**SHACL** — `core:TopicContentShape`가 `contentKind`가 `source-grounded-draft`면 `core:contentSourceLocator`를 **정확히 하나** 요구한다(`sh:or`로 기계 파생만 면제). `core:SourceLocatorShape`는 인쇄 쪽 locator에 쪽번호·절·출처 문서를, STAS locator에 endpoint·레코드 ID·수집일·응답 해시를 모두 요구한다. 적대 fixture `bad:unsourced-authored-draft`(초안인데 locator 없음)가 위반 코드 **`UNSOURCED_AUTHORED_DRAFT`**로 검출되며, 이로써 적대 fixture 위반 코드는 11 → 12가 됐다.

**STAS locator는 어휘만 예약**: `core:locator-stas-record`와 `core:stasEndpoint`·`core:stasRecordId`·`core:collectedAt`·`core:fileSha256`는 TBox와 shape에만 있고 **데이터 배출은 0건**이다. 3절의 재사용 판정에 따라 "어디서 읽었는지"만 기록할 자리를 만들어 두고 본문은 담지 않는다.

**새 역량 질문 SCQ 21** (`ontology/queries/scq-21-k12-core-vocabulary.rq`): `core:facetKey`와 `core:layerConcept`를 개념별로 집계한다. 이 질의문은 초등 저장소의 **CQ 18(`cq-18-k12-core-vocabulary.rq`)과 파일 내용이 완전히 동일하다** — 접두어도, WHERE 절도, GROUP BY·ORDER BY도 같다. 두 저장소가 같은 질의로 읽힌다는 주장을 문자열 동일성으로 증명한다. 중등 결과 행 수 10(facet 8 + layer 2)은 `ontology/queries/expected.json`에 고정했다.

**교차 참조 10건**: 직업계 official 298건 중 10건은 일반 고교 성취기준을 선수로 가진다. 별책26 미용전문교과 해설이 예술 계열 「미술 전공 실기」의 `[12미전02-04]`·`[12미전03-02]`를 헤어·피부·네일·메이크업 과목의 선수 지식으로 지목하기 때문이다(해설 p.58 8건, p.86 1건, p.125 1건). 두 고교 릴리스가 하나의 ID 네임스페이스를 공유하므로 검증기는 직업계 관계의 선수 참조를 `high ∪ high-vocational` 주제 집합으로 해석한다. **반대 방향은 거부한다** — 일반 릴리스의 관계가 직업계 주제를 참조하면 dangling reference로 실패한다. 일반 릴리스가 직업계 없이 단독으로 성립해야 하기 때문이다.

**UI**: 직업계 과목의 상세 페이로드는 `ui/data/high-vocational/`(528개 파일)로 옮겨 지연 로딩한다. 일반 고교와 중학교 과목은 `ui/data/courses/`에 그대로 둔다. `ui/data/map-index.json`은 집계·필터에 쓰는 783개 과목 인덱스 행을 그대로 유지하고 크기도 662 KB 수준으로 커지지 않았다. 통계에 `highVocationalOfficialRelations`(298)가 추가되었고, `highCourses`(759)·`highStandards`(50,749)는 두 릴리스의 합계다.

### 8.5 ID 불변

분리는 레코드가 어느 파일에 있느냐만 바꾸고 ID는 바꾸지 않는다. 근거는 빌더 구조 자체다.

- `scripts/build-curriculum-data.mjs`는 고등학교를 `buildProfile('high')` **한 번의 패스**로 만든 뒤 `programScopes`에 `specialized-vocational`이 있는 과목을 기준으로 컬렉션을 갈라 두 릴리스에 쓴다. 해시 입력에 프로필 이름이 들어가지 않으므로 두 릴리스의 레코드는 모두 `kr.*.2022.high.*` 네임스페이스를 유지한다.
- 직업계 파일의 관계 ID도 `kr.learning-relation.2022.high.*`이다.
- 교과군이 일반·직업계 과목을 섞고 있으면 빌더가 즉시 실패하도록 단언을 두어, 두 릴리스의 `subject-groups`가 겹치지 않음을 매 빌드에서 확인한다.

### 8.6 build:data 멱등화

`bun run build:data`를 두 번 돌리면 R2/R3에서 만든 관계·검토·갭 파일이 시드값으로 되돌아가는 문제가 있었다.

**원인**은 소유권이다. `writeProfile()`이 `middleCollections`/`highCollections`/`bridgeCollections`에 나열된 **모든** 컬렉션을 다시 썼는데, 그 객체들이 `learningRelations: []`(`buildProfile`은 항상 빈 배열을 반환), `reviewRecords: []`, `transitionAlignments: []`, `courseRelations: []`와 커버리지 갭 시드값을 하드코딩하고 있었고 `release.json`의 `counts`도 같은 객체에서 만들어졌다. `rebuild:all`의 **순서는 원래 맞았다**(`build:data` → `build`) — 문제는 순서가 아니라 어느 스크립트가 어느 파일을 소유하는가였다.

**수정**은 소유권을 명시한 것이다.

- `build:data`는 공식 PDF에서 직접 파생하는 컬렉션만 쓴다: `subject-groups`·`courses`·`domains`·`standards`·`topics`·`clusters`, 일반 고교는 여기에 `credit-rules`·`choice-sets`·`pathways`.
- 관계·검토·갭 파일은 `build:relations`/`build:candidates`가 소유한다. `build:data`는 `derivedCollections` 표에 파일명만 선언하고, 카운트는 기존 `release.json`·`inventory-report.json`에서 그대로 이어받는다.
- 커버리지 갭의 표준 문안(문서 권리 검토 갭, 전문가 검토 갭)은 `scripts/build-learning-relations.mjs`로 옮겼다.

**결과**: 깨끗한 트리에서 `bun run build:data && bun run build`를 두 번 돌려도 `git status`가 비고 manifest 해시가 같다.

## 10. 주제 역할·facet 축약과 소규모 정합 (R8-M)

K-12 공통 계약 8·9절의 중등 항목이다. 집필 보고가 반복해서 지목한 "한 성취기준을 facet 3~5개로 나누는 것이 인위적인" 유형을 데이터에 표시하고, 오버레이 최소 길이와 `alignmentKind`를 계약에 맞췄다.

### 10.1 topicRole·collapseInto·collapseReason

주제 ID·오버레이·bridge·관계가 모두 주제 단위를 참조하므로 **주제를 삭제하지 않고 역할을 표시**했다. 주제 1건도 추가·삭제되지 않았고 ID는 전부 불변이다.

| 필드 | 값 |
| --- | --- |
| `topicRole` | `anchor`(중학교 714 + 고교 일반 3,124 + 직업계 47,625) · `facet`(중학교 1,425) · `auxiliary`(중학교 21) |
| `collapseInto` | `auxiliary` 21건이 같은 성취기준의 `anchor` 주제를 가리킨다 |
| `collapseReason` | `overlapping-facets` 7 · `process-standard` 6 · `attitude-standard` 5 · `metacognitive-standard` 3 |

축약 규칙 파일은 `scripts/lib/facet-collapse-rules.mjs` **17건**이다. 집필·검토 보고가 지목한 성취기준만 넣었고(추측 금지), 규칙마다 `note`에 근거 보고를 적었다.

| 과목 | 성취기준 | auxiliary facet | reason |
| --- | --- | --- | --- |
| 수학 | `[9수01-08]` `[9수02-21]` `[9수03-17]` | `representation` + `application` | `overlapping-facets` |
| 수학 | `[9수04-04]`(통계적 탐구) | `representation` + `application` | `process-standard` |
| 국어 | `[9국01-11]` `[9국02-08]` `[9국03-08]` | `reflection` | `metacognitive-standard` |
| 국어 | `[9국01-10]` `[9국03-09]` `[9국05-09]` | `reflection` | `attitude-standard` |
| 과학 | `[9과01-03]` `[9과02-05]` | `inquiry` | `attitude-standard` |
| 과학 | `[9과18-01]` `[9과22-01]` `[9과23-01]` `[9과23-02]` | `inquiry` | `process-standard` |
| 과학 | `[9과22-02]` | `inquiry` | `overlapping-facets` |

빌드는 규칙이 존재하지 않는 성취기준 코드를 가리키거나 분해가 만들지 않는 facet을 지목하면 실패한다. 규칙표가 분해 정책과 어긋난 채 남아 있을 수 없다.

### 10.2 자동 축약 후보 판정

`check:content`가 같은 성취기준에 걸린 두 `source-grounded-draft` 주제의 `evidence` + `assessmentPrompts` 토큰 자카드 유사도를 계산하고, **0.6 이상**이면 `overlapping-facets` 축약 후보로 보고한다. 규칙 파일에 없는 후보는 경고만 내고 빌드를 실패시키지 않는다.

현재 중학교 authored 형제 쌍 2,295건의 최대 유사도는 **0.25**(`[9수03-11]` core↔representation)여서 자동 후보는 **0건**이다. 집필자가 형제 facet마다 서로 다른 어휘로 증거·과제를 썼기 때문이며, 그래서 축약 판정의 권위는 규칙표에 있고 자동 판정은 회귀 감시 장치다.

### 10.3 게이트

- `validate.mjs`: 성취기준당 `anchor` 1개, `auxiliary`의 `collapseInto`가 같은 성취기준의 non-auxiliary 주제를 가리킴. official 관계 층과 bridge의 endpoint가 `auxiliary`면 **경고**(공식 전개는 anchor를 쓰므로 0이어야 한다) — 실제 **0건**.
- 스키마: `core.schema.json`에 `topicRole`·`collapseReason` 통제 어휘, 중학교 프로필은 `standard-core` ↔ `anchor` 동치와 `collapseInto`/`collapseReason`의 auxiliary 전용 규칙을, 고교 프로필은 `topicRole: anchor` 고정을 강제한다.
- SHACL: `core:AnchorUniquenessShape`(성취기준당 anchor 정확히 1개), `core:TopicRoleShape`(역할 어휘 3종, `collapseInto`는 auxiliary 전용). 적대 fixture에 `DUPLICATE_ANCHOR_ROLE`·`AUXILIARY_WITHOUT_COLLAPSE_TARGET` 2종을 추가했다.
- SPARQL: `scq-22-topic-role-collapse.rq` 신설. 두 모드 모두 21행(auxiliary 주제 → anchor 주제)을 돌려준다.
- UI: `auxiliary` 주제를 성취기준 상세 안의 접힌 `축약 주제 N개 — 대표 주제로 대신합니다` 블록으로 옮기고, 세부 주제·관찰 증거·평가 질문 목록은 non-auxiliary 주제만 보여 준다.

### 10.4 온톨로지 어휘

`ontology/k12-core.ttl`에 `core:topicRole`·`core:collapseInto` 속성과 `core:TopicRoleScheme`(anchor·facet·auxiliary 3종)을 추가했다. 코어 IRI·versionIRI(`…/k12-core/1.0.0`)는 그대로 두고 헤더의 동기화 기준 해시만 갱신했다(`cb2c8da7…` → `dba64373…`). 개념 IRI는 초등 저장소와 합의한 `core:topic-role-anchor`·`core:topic-role-facet`·`core:topic-role-auxiliary`이며, 파일은 두 저장소가 바이트 동일(`31f9c331…`)하고 `tests/k12-core-sync.test.mjs`가 검사한다.

### 10.5 소규모 정합 (계약 9절)

- **오버레이 `evidence` 최소 길이 25자 → 20자.** 한국어 관찰 행동 문장이 20~24자에서 자연스럽게 끝난다는 집필 보고 4건에 따른다. `prompt` 40자·`misconception` 15자는 유지한다. `schema/content-overlay.schema.json`·`scripts/lib/content-overlay.mjs`의 `OVERLAY_MIN_LENGTHS`·데이터 계약 5.1절·테스트를 함께 바꿨다. 기존 오버레이 24파일 2,160엔트리는 전부 그대로 통과한다.
- **`standard-core` 주제의 `alignmentKind` `supports` → `assesses`.** 성취기준 전체를 대표·평가하는 주제라는 뜻이다. 714건이 바뀌었고 `subject-facet` 주제의 `introduces` 22 · `supports` 1,280 · `extends` 144는 유지된다. 주제 ID 해시 입력은 `standardId`와 `facetKeyDetail`뿐이라 이 변경은 ID를 건드리지 않으며, `tests/topic-roles.test.mjs`가 중학교 2,160건의 ID를 해시로 재계산해 확인한다.


## 이 릴리스의 게이트

이 보고서는 게이트를 실행하지 않는다. 릴리스 전 오케스트레이터가 아래를 순서대로 돌린다.

```
bun run verify            # build → validate → validate:ontology → validate:shacl
                          # → validate:sparql → check:content → test → check
bun run verify:official    # 위에 더해 공식 원본 해시 재대조
bun <gates>/sec-layers.mjs   # 층 불변식·층별 DAG·합집합 DAG·층 간 중복
bun <gates>/sec-hygiene.mjs  # 공백 위생·ID 안정성·메타데이터
```

원장과 실데이터에서 확인된 값은 다음과 같다.

- 중·고 학습 그래프 DAG, 고교 과목 그래프 DAG, dangling reference 0, duplicate ID 0 (`data/kr/relation-coverage-report.json`의 `validation`)
- 테스트 **72건** (`tests/` 10개 파일: content-overlay 13 · relation-layers 13 · schema-contract 10 · topic-roles 10 · release-artifacts 6 · text-normalize 6 · ui-contract 5 · printed-page-offsets 4 · k12-core-sync 3 · manifest 2)

## 남은 한계·후속 과제

- **사회·역사 초→중 영역 대응표가 비어 있다.** 두 저장소의 `domain`이 모두 단원명이라 내용 체계표 영역으로 가는 대응을 확정할 수 없다. 대응표를 만들기 전까지 이 두 교과의 후보 bridge는 0건이다.
- **로마숫자 표기 정규화 미결.** 저장소는 라틴 `I`, 고시 원문·STAS는 전각 `Ⅰ`(U+2160)을 쓴다. 76건이 이 차이 하나로 어긋난다. 어느 쪽으로 통일할지 결정하면 고교 성취기준 ID 재생성 여부까지 함께 판단해야 한다.
- **facet 축약은 표시로 해결했고 분해 규칙 자체는 그대로다.** 10절의 `topicRole`·`collapseInto`는 인위적인 facet을 튜터가 건너뛰게 만들 뿐, 과목별 facet 개수(국어 4·도덕 5·기술가정 2·나머지 3)를 바꾸지 않는다. 규칙표 17건은 집필 보고가 지목한 성취기준만 담으므로 보고되지 않은 인위적 분해는 아직 드러나지 않은 채로 남아 있다. 자동 판정(자카드 ≥ 0.6)은 집필 어휘가 서로 달라 현재 0건을 잡으므로, 남은 후보는 교과 전문가 검토에서 나와야 한다.
